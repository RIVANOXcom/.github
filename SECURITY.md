
# RIVANOX Security Policy

## Security Principles

RIVANOX prioritizes responsible software engineering, privacy, system reliability and secure development practices.

Responsible vulnerability reports and constructive security research are appreciated.

## Reporting Security Vulnerabilities

Potential security vulnerabilities should not be disclosed through public GitHub issues or discussions.

If private vulnerability reporting is available for the affected repository, that reporting channel should be used.

Otherwise, official contact information is available at:

https://rivanox.com/legal-notice/

General technical support:

https://rivanox.com/support/

## Recommended Report Information

A useful vulnerability report should include:

- Affected software or component
- Version or release information
- Relevant operating system or environment
- Description of the suspected vulnerability
- Steps to reproduce the issue
- Potential security impact
- Relevant technical evidence, where appropriate

Sensitive information such as credentials, access tokens, customer data or private repository contents must not be shared publicly.

## Responsible Disclosure

Security researchers are requested to avoid unauthorized access, service disruption, destructive testing and unnecessary exposure of confidential information.

Potential vulnerabilities should be reported privately to allow appropriate investigation.

## Supported Versions

Supported versions and security update availability depend on the affected product.

Product-specific information is maintained through the applicable documentation and official website.

## Security Response

Security reports are reviewed through the available official contact channels.

Investigation and remediation depend on the nature, severity and reproducibility of the reported issue.

No fixed response or remediation deadline is guaranteed by this general policy.
